# M1 — 数据管道 + 睡眠窗系统（L1/L2/L4）+ 睡眠评分

## 目标
建立从 HealthKit 到本地存储的数据管道；实现睡眠窗 L1（原生窗口）/ L2（自动延长）/ L4（人工校正数据模型）与睡眠评分 v1 + 置信度角标。双端调试页可见「今晚睡眠」区块。**本阶段无产品 UI**（概览页是 M2）。

## 范围边界
- ✅ 做：增量同步引擎（锚点持久化）、本地存储、睡眠窗构建器（含 L2 规则引擎与手表后台唤醒）、L4 校正数据模型与重算、睡眠评分 v1、调试页展示、单测
- ❌ 不做：产品概览页（M2）、Recovery/Strain（M2）、打卡/通知（M3）、后台刷新任务的推送通知（M3）、WatchConnectivity 跨端同步（M7）、任何 UI 美化

## 交付物

### 1. `Shared/Store/` — 本地存储（SwiftData）
模型严格按 design.md §4 表：
- `RawSample`：type, value, start, end, source, hkUUID；缓存 90 天，之后降采样为日聚合（M1 先做 90 天滚动清理）
- `SleepWindow`：start, end, segmentsJSON, source(l1Native/l2Extended/l4Corrected→存字符串), confidence, version, dayKey（窗口起始日）；**L4 = 新 version 记录 source=override，保留全部历史版本**
- `DailyMetric`：date + recovery/sleepScore/sleepNeed/sleepDebt/strain/acwr/stress/confidenceJSON（M1 只填 sleepScore 与 confidenceJSON，其余字段留空）
- `Baseline`：metric, median, mad, computedAt（28 天滚动；M1 实现每日重算 restingHR/HRV/呼吸/腕温 四项）

### 2. `Shared/HK/HKSyncEngine.swift` — 增量同步
- 每类型一个 `HKAnchoredObjectQuery`，anchor 持久化到 UserDefaults（key 按类型）
- 冷启动：全量回填最近 60 天 → 之后增量；删除事件（`HKDeletedObject`）同步处理
- `HKObserverQuery` 订阅变化 → 触发增量拉取（仅前台 + 手表后台唤醒时段）
- 采样落库前先按保留策略聚合（聚合规则放 `Shared/Store/Aggregator.swift`，纯函数可测）

### 3. `Shared/Sleep/SleepWindowBuilder.swift` — 睡眠窗引擎（核心）
- **L1 段清洗**（design.md §6 原文）：合并 gap≤20min 的 asleep 段；丢弃 <5min 的 awake 段（HR 上升>15bpm 的豁免判定留参数，M1 默认丢弃并在注释标 TODO-M1+）；剔除 inBed 但活动能量异常段（M1 以 inBed 段不并入 asleep 窗实现，活动能量校验留 TODO）
- **L2 延长规则**（design.md §6 原文）：窗口结束后 3h 内，每次后台唤醒检查：`步数==0 && 站立==0 && 活动能量<1kcal/min && 心率≤夜间中位数+8 && 未充电` → 延伸窗口至最新样本（source=.extended）；连续 3 次不满足 → 锁定。夜间心率中位数取该窗口内 RawSample 的 1min 聚合
- **Confidence**（design.md §6 原文）：0.4·HR覆盖率 + 0.3·分期连续性 + 0.3·窗内静止比例 → ●(≥0.8) ◐(0.5–0.8) ○(<0.5)，附原因文案
- **L5 追溯重算**：拉到新样本即重算当日窗口与评分，version+1
- **后台唤醒**：Watch 端 `BGAppRefreshTask`（identifier `com.pulse.l2check`，仅窗口结束后 3h 内调度，earliest 15min，检查完 cancel 未执行任务防刷电）；iPhone 端不跑 L2

### 4. `Shared/Scoring/SleepScore.swift` — 评分 v1
design.md §9 原文：`Sleep = 40·时长分 + 25·效率 + 20·结构偏离 + 15·规律性`（各分量 0–1；结构偏离=实际分期结构与个人 28 天基线的偏离度反向分，M1 用恒等 0.5 占位并在代码注释标 TODO-M2；规律性=入睡中点 σ，M1 无历史则按 0.5 占位）
基线门控：前 14 天校准期不出总分——输出分项 + 标注「标定期」
纯函数，输入分项与 baselineReady，输出分项+总分(可空)+confidence。

### 5. UI（仅调试页追加区块）
- 手表 DebugDataView 底部加「今晚睡眠」：窗口时段（大字 ≥17pt SF Rounded）、时长/效率、评分、置信度徽章、L2 延长次数；颜色用 systemGreen/Orange/Red 三档
- iPhone DebugDataView 同步区块（读同一存储层；手机端数据=手机自身 HealthKit）
- 触发按钮「重新计算」手动跑一遍 L1+L2+评分（便于验证）

### 6. 单测（XCTest，挂 PulsePhone target，模拟器可跑）
`PhonePulseTests/`（新建）：
- L1：基础窗口合并（gap≤20min）/跨日窗口 dayKey 归属（窗口起始日）/ <5min awake 段丢弃
- L2：合成样本集验证「延长成功 / 步数>0 拒绝 / 3 次失败锁定」
- 评分：效率 100%/60%/40% 三例总分；基线缺失行为
- 至少 12 个 case

## 验收标准
1. `xcodebuild -scheme PulsePhone -destination 'generic/platform=iOS Simulator' test` 全绿
2. 手表端 `swiftc -typecheck` 通过（命令见 M0.md）
3. BGAppRefreshTask 电量说明写进代码注释：仅在窗口后 3h 内调度
4. 双评审通过（产品评审重点：调试页信息层级、角标诚实性；代码评审重点：聚合正确性、SwiftData 主线程约束、后台任务不泄漏）

## 设计红线（违反=REWORK）
- 睡眠数据**绝不**写回 HealthKit；L2/L4 结果只存本地
- 所有派生数据带 SampleSource 标注
- 无插值、无猜测：缺口就标缺口
- 后台唤醒不得无限续命：3h 上限硬编码

### Orchestrator 决策

1. **watchOS 后台任务改用 `WKExtension.scheduleBackgroundRefresh`**：watchOS 没有 BackgroundTasks 框架，原计划的 `BGTaskSchedulerPermittedIdentifiers` 从 Info.plist 移除
2. **L2 延伸回滚保护**：`rebuildNight` 与「最近的 system 版本」比对，extended 版本 end 不被 L1 重算覆盖 —— 原设计文档未覆盖此竞态
3. **占位分不入总分**：结构与规律性缺历史时按权重重归一化，避免校准期后固定虚高 17.5 分
4. **子代理审查策略调整**：长输出任务会触发 `Upstream stream failed`，改为窄范围多次审查 + orchestrator 汇总；后续 M2 起沿用此策略
