# M0 阶段规格：工程骨架 + HealthKit 授权 + 调试数据页

## 目标
建立可编译、可安装的最小双端工程，打通 HealthKit 授权与读取链路，提供「原始数据调试页」证明数据通路。

## 输入
- docs/design.md（架构/约束/数据模型/读写清单）
- PLAN.md（免费证书约束）

## 交付物
```
Pulse.xcodeproj/                 ← 手写 minimal pbxproj；共享 schemes：
                                   PulseWatch（watchOS）、PulsePhone（iOS）
WatchPulse/                      ← watchOS App Target（单 Target，无 Extension）
  ├── WatchPulseApp.swift        ← @main + 授权流程触发
  ├── ContentView.swift          ← TabView 骨架（今日/训练/趋势/设置，占位）
  ├── DebugDataView.swift        ← 调试页：最近 24h 各类样本计数+最新值+时间戳
  └── Assets.xcassets, Info.plist, WatchPulse.entitlements
PhonePulse/
  ├── PhonePulseApp.swift
  ├── ContentView.swift          ← 首页占位 + 授权状态卡
  ├── DebugDataView.swift        ← 调试页：样本明细列表（类型/值/时间/来源）
  └── Assets.xcassets, Info.plist, PhonePulse.entitlements
Shared/
  ├── HK/HKService.swift         ← 授权请求（design.md §10 全部读类型）+ 查询封装
  ├── HK/HKTypes.swift           ← 类型注册表（quantity/category 映射）
  ├── Model/SampleSource.swift   ← 来源枚举
  └── Model/DebugSample.swift    ← 调试页用纯值模型
scripts/resign.sh                ← 免费证书重签+重装脚本（骨架，含使用说明注释）
README.md                        ← 工程说明、构建命令、真机安装步骤
```

## 关键要求
1. **手写 pbxproj**：无 XcodeGen/Tuist 依赖；签名 `CODE_SIGN_STYLE=Automatic`、`DEVELOPMENT_TEAM=""`（用户 Xcode 内选择）；Bundle ID：`com.boshi.watch` / `com.boshi.phone`。
2. **Entitlements**：两个 Target 均 `com.apple.developer.healthkit=YES`；**禁止 App Groups / iCloud / Push**。
3. **Info.plist**：`NSHealthShareUsageDescription` 中文文案；watchOS 端 `WKWatchOnly` 不限制（独立 App）。
4. **授权流程**：App 启动时请求 design.md §10 全部读类型；未授权时调试页显示「等待授权」+ 跳设置提示；授权后自动刷新。
5. **调试页**（本阶段唯一用户可见功能）：
   - 手表：每类一行「类型 · 最新值 · 更新时间 · 24h 计数」，下拉刷新。
   - 手机：列表 + 点入看明细（值/起止时间/来源）。
   - 数据为空时显示「暂无数据」（不得崩溃）。
6. **部署目标**：watchOS 11.0 / iOS 18.0；Swift 5 模式（不开 Swift 6 严格并发）。
7. **模拟器可编译通过**（真机 HealthKit 数据为空属正常，用空态处理）。
8. scripts/resign.sh：用 `xcodebuild` 构建 + `devicectl`/`xcodebuild` 安装，顶部注释说明免费证书 7 天续签流程。

## 验收标准
- [ ] `xcodebuild -scheme PulseWatch -destination 'platform=watchOS Simulator,...' build` 通过
- [ ] `xcodebuild -scheme PulsePhone -destination 'platform=iOS Simulator,...' build` 通过
- [ ] 交付物文件树与上表一致
- [ ] 无网络请求代码；无 App Groups/iCloud/Push entitlement
- [ ] 授权类型清单与 design.md §10 完全一致
- [ ] 空数据/未授权有明确 UI 状态

## 非目标（本阶段不做）
评分算法、睡眠窗口、训练识别、WCSession 同步、SwiftData 持久化（仅骨架）、任何 UI 美化。

## 自检
执行者须自行运行两个 scheme 的 xcodebuild，将结果附在交付汇报中。模拟器 destination 先用 `xcrun simctl list devices available` 选存在的设备名。

### Orchestrator 决策（超出规格处，均已在 nits.md 记录）
1. **工程生成方式切换为 XcodeGen**（project.yml 为唯一工程源）。原因：手写 watchapp2 pbxproj 遭遇「Multiple commands produce」lipo 冲突，深挖后发现与本机 Intel + Xcode 26 的 watchsimulator 平台缺陷有关，非工程文件问题；XcodeGen 消除了后续各阶段手写 pbxproj 的维护风险。规格中原「无 XcodeGen/Tuist 依赖」条款作废。
2. **确认本机为 Intel Mac**：watchOS 26 模拟器不可用于本机（平台缺陷，XcodeGen 工程对照实验证实）。手表端验证 = swiftc typecheck（每阶段）+ 真机 S9（resign.sh）。iOS 26.3.1 模拟器可用，手机端不受影响。
3. 手表模拟器 Runtime 5.17GB 下载、iOS 26.3.1 Runtime 下载：均已完成（为后续 iPhone 端 UI 测试保留 iOS 模拟器）。
